# Tasks

If you use an issue tracker (GitHub Issues, Linear, monday.com, Jira), this file should be a thin pointer to it. Don't duplicate tasks here — pick one source of truth.

## Where tasks live

_e.g., GitHub Issues: https://github.com/org/repo/issues_
_e.g., Linear board: https://linear.app/team/project_

## Conventions

### Labels

- `p0` — drop everything, fix now
- `p1` — important, fix this week
- `p2` — needed, schedule it
- `p3` — nice to have

### Types

- `bug` — something broken
- `feature` — new capability
- `chore` — maintenance, refactor, deps
- `docs` — documentation only
- `infra` — infrastructure, deployment, CI

### Ownership

Every active issue should have one assignee. Unassigned = unowned = nobody's doing it.

## When to use this file directly

- Sprint planning notes that don't fit in the tracker
- Cross-cutting work breakdowns spanning many issues
- Otherwise: use the tracker.
